Dispatch

A last-mile delivery telemetry pipeline: Kafka → Spark Structured Streaming → a bronze/silver/gold lake → a star schema, orchestrated by Airflow, with dbt marts and nine blocking data-quality gates.

What it is built around

  • A replay must not change the answer. Kafka is at-least-once, so duplicates arrive; a producer also re-sends corrected events, which DISTINCT keeps as separate rows. Identity is declared instead — 5,948 redeliveries collapsed, 1,155 corrections applied.
  • A null is not a fact. A trip with no delivered event is either in flight or its event has not arrived. Trips carry a completeness label, and only completed ones enter an average.
  • A LEFT JOIN that behaves as INNER raises nothing. It just returns a smaller, reasonable-looking table. A gate asserts row counts survive the join.
  • Gates run before the load, not after. A validate step downstream of a load means the bad rows are already being read.
  • The logic imports no engine. Nothing under dispatch/ imports Spark, Kafka or Airflow, so 94 tests and a full run execute in CI with no containers.

The data

  • Events are generated, not downloaded, by a seeded script in the repository. Public datasets are clean, and a clean dataset cannot exercise a quality gate.
  • Defects are injected deliberately and each rate is tunable: redeliveries, corrections, late arrivals, two timestamp serialisations, mixed schema versions, undeclared fields, lifecycle violations.
  • So the per-store finding on the results page is a demonstration, not a validated model — the marts recover speeds the generator put there. What is not circular is that a pooled average hides the split.
